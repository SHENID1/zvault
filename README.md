# 🛡️ ZVault (ZCode Secret Masking & Security Gateway)

Локальный защитный шлюз для AI-редактора **ZCode** при работе со сторонними или непроверенными LLM API (`agentrouter.org`, китайские реселлеры, приватные эндпоинты).

---

## 🎯 Архитектура работы

```
ZCode (Ваш редактор)
       │  (Запрос с кодом / промптом: sk-live-98765...)
       ▼
[Локальный Шлюз 127.0.0.1:8765]
       │  1. Перехватывает messages / tool_calls
       │  2. Заменяет секреты на типизированные плейсхолдеры (__VAULT_API_KEY_01__)
       │  3. Сканирует входящие промпты на Prompt Injections & обфускацию
       ▼
Сторонний LLM API (agentrouter.org / реселлеры / VPS)
       │  Видит плейсхолдер __VAULT_API_KEY_01__ вместо реального ключа
       ▼
[Локальный Шлюз 127.0.0.1:8765]
       │  4. В потоке SSE (включая tool_calls) на лету восстанавливает
       │     __VAULT_API_KEY_01__ обратно в код с корректным экранированием JSON
       ▼
ZCode (Ваш редактор)
       Получает рабочий готовый код с восстановленными секретами.
```

## 🚀 Быстрый старт

### 1. Установка зависимостей
```bash
pip install -r requirements.txt
```

### 2. Запуск шлюза
Через скрипт запуска:
* **Windows:** `run.bat`
* **Linux / macOS:** `./run.sh`

Или через CLI:
```bash
python cli.py start
# или при установленном алиасе:
zv start
```

Шлюз стартует на `http://127.0.0.1:8765`.

## ⚙️ Настройка ZCode

В ZCode в настройках провайдеров (или в файле `~/.zcode/v2/provider_config.json`) измените `baseUrl` нужного провайдера:

### Вариант А: Именованный маршрут (Рекомендуется)
Если в `config.json` прописан upstream:
* **Было:** `https://agentrouter.org/v1`
* **Стало:** `http://127.0.0.1:8765/agentrouter/v1`

### Вариант Б: Универсальный маршрут (Без правок config.json)
Для любого нового сервиса без перезапуска прокси:
* `http://127.0.0.1:8765/proxy/https/<целевой_домен>/v1`
* Например: `http://127.0.0.1:8765/proxy/https/agentrouter.org/v1`

## 🔒 Возможности защиты

1. **Автодетект по сигнатурам и контексту кода:**
   - OpenAI / Anthropic (`sk-...`, `sk-ant-...`)
   - Google AI Studio (`AIza...`)
   - GitHub PAT (`ghp_...`, `github_pat_...`)
   - Telegram Bot API токены (`\d{9,10}:...`)
   - AWS ключи (`AKIA...`), Stripe (`sk_live_...`, `rk_live_...`), JWT токены
   - SSH/RSA приватные ключи (`BEGIN PRIVATE KEY`) и публичные ключи
   - IPv4 и IPv6 адреса (с валидацией через `ipaddress` и исключениями для localhost)
   - Контекстные присваивания (`token = "..."`, `export STRIPE_KEY=...`)
2. **Анализ энтропии Шеннона ($H \ge 3.85$):**
   - Автоматически находит случайные ключи и токены длиной от 20 символов даже без явных префиксов (с исключением системных ID вроде `call_*`).
   - Эмпирическая точность обнаружения: ~92–94% для случайных base36-токенов (`[a-z0-9]`, 26+ символов) и ~99.9% для base62 (`[a-zA-Z0-9]`).
   - Шестнадцатеричные (hex-only) последовательности (например, Git commit SHA, хеши MD5/SHA-256) имеют теоретический максимум энтропии $\log_2(16) = 4.0$ и практическую энтропию ~3.5–3.6. Они намеренно не маскируются общим энтропийным сканером, чтобы исключить порчу коммитов, хешей файлов и селекторов (для них маскирование работает через контекстные присваивания или `.env`/`secrets.json`).
   - Поддерживает 88-символьные base64-ключи Azure Storage, длинные буквенно-цифровые токены (до 512 символов) и составные ключи со словарными префиксами (`live_secret_key_<случайный хвост>`, `prod-api-key-...`, `my_service_token-...`).
   - Настраиваемое время жизни (TTL) динамических секретов: параметр `"state_ttl": 86400` в `config.json` (по умолчанию 24 часа; фоновый сборщик очищает устаревшие секреты каждую минуту).
3. **Prompt Injection Guard:**
   - Перехват попыток сброса инструкций (`ignore previous instructions`, «Игнорируй все предыдущие инструкции»).
   - Детект обфускации: декодирование Base64, очистка Zero-Width Unicode (`\u200B`), нормализация гомоглифов (кириллические символы-двойники).
   - Блокировка опасных команд (`curl | bash`, `Invoke-WebRequest | iex`, `rm -rf /`).
   - Сканирование только свежих сообщений и `tool_result`, что исключает перманентную блокировку всей сессии.
   - Опция `block_tool_results: true` для строгой блокировки Indirect Prompt Injection (по умолчанию `false`, чтобы не блокировать агента при чтении файлов с примерами атак).
4. **Сетевая изоляция и безопасность:**
   - **Host Header Validation:** защита от DNS Rebinding атак.
   - **X-Vault-Token:** авторизация для эндпоинтов управления (`/vault/*`, `/test-echo`).
   - **Fail-Closed:** при любой ошибке маскирования шлюз отдает 500 и блокирует отправку незамаскированных данных на апстрим.
   - **SSRF Whitelist:** проверка `allowed_hosts` без следования слепым редиректам (`follow_redirects=False`).

## ⚠️ Модель угроз и ограничения (Threat Model)

* **Эвристический характер:** маскирование строится на сигнатурах, энтропии и синтаксическом контексте. Оно не может гарантировать 100% перехват секретов, если они закодированы сложным пользовательским шифром или разбиты на части в промпте.
* **Короткие суффиксы и пассфразы:** составные токены со случайными хвостами длиной 12 символов и менее намеренно не маскируются эвристикой (порог обнаружения случайного сегмента — от 16 символов) во избежание конфликтов с версионными тегами (`v1`, `v2`, `build_1`). Многословные парольные фразы (`correct_horse_battery_staple_...`) состоят из словарных слов и требуют явного контекста присваивания (`password = "..."`) или предварительного добавления в `.env`/`secrets.json`.
* **Демаскирование в ответах:** поскольку шлюз восстанавливает секреты для редактора ZCode, успешная атака типа Indirect Prompt Injection в контексте может побудить модель вызвать инструмент с плейсхолдером, который при демаскировании восстановит реальный секрет. Рекомендуется использовать режим `action: "block"` в `injection_guard`.
* **Локальный доступ:** шлюз предназначен исключительно для локального использования на машине разработчика (`127.0.0.1`). Не экспонируйте порт `8765` во внешнюю сеть.
